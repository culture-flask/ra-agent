# 单向量检索 vs 混合检索：第三轮测试报告（2026-08-16）

> 本轮由 ZCode 执行。上一轮报告（DeepSeek 版）见 `retrieval_eval_report.md`，本轮参考了它的框架，
> 但重新设计了全部测试用例（设计与修正原因见 §4.3），并用对话级测试交叉验证了离线结论。

---

## 0. 一句话结论

**建议保持 hybrid（混合检索）作为默认模式**——它在关键词式查询下大幅优于纯向量（MRR 0.875 vs 0.497），
在自然语言长查询下与纯向量打平（各有 1-2 个用例互有胜负），几乎没有场景明显更差；
代价只有每次查询约 0.02 秒的额外耗时。但要清楚：**hybrid 不是在所有查询下都更好**，
长自然语言查询里 BM25 一路会被"常见词"稀释、偶尔还会把纯向量能找到的结果挤出前十（详见 §5.3 机制剖析）。

## 1. 两种检索方式是怎么工作的（概念讲解）

### 1.1 单向量检索（vector）

把每个文档片段（chunk）和用户问题都送入一个**嵌入模型**（本项目用的是 qwen3-embedding:8b，
本地 llama.cpp 部署），转换成一个高维数字向量（4096 维）。语义相近的文本，向量在空间中的距离也近。

检索时：把问题变成向量 → 在向量库（Chroma）里找**距离最近**的 k 个片段 → 返回。

- 结果里的 `distance` 字段就是问题向量与片段向量的距离，**越小越相关**。
- 优点：懂"意思"。问"怎么区分加密数据和随机数"也能找到讲"neural distinguisher"的英文论文，
  因为两者语义接近，不需要字面相同。
- 缺点：对**精确的缩写、论文标题、人名、专有名词**不敏感。"HDND"这四个字母的向量，
  和含 "HDND" 的片段向量未必最近——嵌入模型看到的是整体语义，不是字面。

### 1.2 BM25（关键词检索，hybrid 的一路）

经典的关键词打分算法，思想可以概括为三句话：

1. 查询词在某个片段里**出现得越多**，这个片段越可能是相关的（词频）；
2. 查询词本身**越罕见**，命中时越有价值（比如 "HDND" 全库只有 29 个片段含有，
   它的区分度远高于 "differential" 这种到处都是的词）；
3. **短的片段**命中同样的词比长片段更可信（长度归一化）。

本项目 BM25 的分词方式（`app/abstractions/bm25.py`）：英文按单词、**中文按两字滑窗（bigram）**切分，
例如"差分区分器"→ `差分 / 分区 / 区分 / 分器`。这带来一个重要特性：
**中文查询词永远匹配不上英文文档**（"傅里叶"三个字在英文论文里一次也不会出现），反之亦然。

### 1.3 混合检索（hybrid）与 RRF 融合

hybrid 同时跑两路：向量检索取前 10、BM25 取前 10，然后用 **RRF（Reciprocal Rank Fusion，
倒数排名融合）**合并。RRF 不看两路的绝对分数（向量距离和 BM25 分数量纲完全不同，没法直接比），
只看**排名**：

```
每个片段的融合分 = Σ 1 / (60 + 该片段在某一路中的排名)
```

比如某片段在向量路排第 1、BM25 路排第 3，融合分 = 1/61 + 1/63 ≈ 0.0323；
一个只在 BM25 排第 1 的片段融合分 = 1/61 ≈ 0.0164。两路都命中的片段天然占优。
最后按融合分取前 k 个。

### 1.4 一个容易误读的字段：`method`

检索结果里每个片段带 `method` 标记：`vector` / `bm25` / `hybrid`。注意实现细节
（`rrf_fuse` 合并时第一路的字段优先）：**一个片段若同时被两路命中，`method` 显示为 `vector`**
（此时它同时带 `distance` 和 `bm25_score` 两个字段，可以据此识别真正的"双路命中"）；
只有 `method=bm25` 才表示"纯靠关键词找到、向量没找到"。

## 2. 测试指标含义（逐个解释）

评测需要先有**金标准（Ground Truth）**：对每个测试问题，人工列出"哪些文档算正确答案"。
有了金标准才能算下面的指标。本轮所有金标准都经过验证（方法见 §4.2）。
指标全部按**文档级**计算：同一篇论文的多个片段只算一次，排名取该文档**首次出现**的位置。

| 指标 | 含义 | 例子 | 衡量什么 |
|---|---|---|---|
| **P@k（Precision@k，精确率）** | 返回的前 k 个文档里，正确文档占几席 | P@10 = 0.2 表示前 10 个里有 2 个是对的 | 返回结果**干不干净**（噪音多不多） |
| **R@k（Recall@k，召回率）** | 应该找到的 gold 文档中，前 k 个结果找回了几成 | gold 有 4 篇、找回 2 篇 → R@10 = 0.5 | **漏没漏**重要资料 |
| **MRR（Mean Reciprocal Rank，平均倒数排名）** | 第一个正确文档排在第几位，取倒数后对所有问题求平均 | 第 1 位得 1.0，第 4 位得 0.25，没找到得 0 | 用户**多快**看到第一条正确结果 |

为什么两个指标都要看：P 高 R 低 = 返回的都挺对但漏得多；R 高 P 低 = 该找的都在但夹在一堆噪音里。
对 RAG 问答来说，**R@k 通常更重要**——生成模型擅长从片段里挑有用的，但检索没带回的内容它无从知晓；
不过 top-k 很小（对话默认 total_k=5）时噪音也会真正挤占名额，所以 MRR（正确文档排多前）同样关键。

另外补充一个本轮实测的**延迟**：两种模式单次检索分别约 0.12s / 0.14s（BM25 索引进程内缓存后），
差异可忽略。

## 4. 测试用例设计

### 4.1 设计原则

上一轮（DeepSeek 版）有 6/13 的用例双模式全 0，没有区分度。本轮先做了归因再出题，
把用例分成五类，并**用磁盘上的 chunk 原文逐一验证金标准**（grep 统计关键词在 81 篇文档中的分布），
确保每个 gold 文档确实包含对应概念、且用例本身可被命中。

| 类别 | 数量 | 查询特征 | 预期 |
|---|---|---|---|
| A-精确专名 | 6 | 缩写/论文标题/工具名（HDND、CPDI-ND、SKNet、SoK…） | BM25 主场 |
| B-算法主题 | 5 | 算法名+任务（Gimli、ASCON/GIFT、SIMECK…） | 两路配合 |
| C-中文问英文 | 5 | 中文语义查询、答案在英文论文（部分解密/傅里叶…） | 向量主场（BM25 天然失效） |
| D-跨语言 | 1 | "多面体差分"中英文各有一篇主力论文 | 观察能否跨语言 |
| E-标题精确 | 1 | Gohr 论文英文标题原题 | 修正上轮失败用例 |

另外补了一组**短关键词查询电池**（8 例，与长查询共享金标准），
因为预实验发现：**同一个意图，问法长短不同，两种模式的相对表现会反转**（见 §5.3）。

### 5.3 机制剖析：三个本轮发现的重要现象

**现象一：BM25 的"常见词稀释"效应（长查询失效的原因）**

用例 #1 "HDND 高阶差分神经区分器是什么"。BM25 把查询切成 11 个词：
`hdnd / 高阶 / 阶差 / 差分 / 分神 / 神经 / 经区 / 区分 / 分器 / 是什 / 什么`。
BM25 分数是**各词得分直接相加**：一篇同时含"差分/区分/神经/分器…"等六七个常用中文词的中文论文片段
（实测 2024Yue 的片段得了 29.5 分），总分反而高于只含 "hdnd" 一个稀有词的目标片段（约 10 分）。
于是目标文档被挤出 BM25 前 10，hybrid 的关键词路等于白跑。
而短查询 "HDND" 只有 1 个词，BM25 一击必中。
**教训：BM25 喜欢关键词式的短查询，讨厌带一堆领域常用词的完整句子。**

**现象二：RRF 融合可能"挤出"向量的深位命中（hybrid 唯一明确变差的场景）**

用例 #18（Gohr 论文标题原题）：vector 模式在第 9 位找到了 2019Gohr.pdf；hybrid 模式反而完全丢失。
原因：该标题里的 attacks / deep / learning / improving 都是全库高频词，BM25 路的前 10 名全是"综述类"
片段；RRF 下 BM25 第 1 名得 1/61≈0.0164，而向量路第 9 名只有 1/69≈0.0145——
**融合排名倾向于两路都靠前的片段，一路深位（第 9、10 名）的命中很容易被另一路的浅位挤掉**。
这解释了为什么长查询里 hybrid 的 R@10（0.583）反而低于 vector（0.639）。

**现象三：中文查询 × 英文文献是两种模式共同的短板**

C 类 5 例中 3 例成功（剪枝量化/架构搜索/侧信道——查询含独特的语义锚点），
2 例失败（部分解密/傅里叶——查询主干仍是"神经区分器"，被同主题中文文档淹没）。
BM25 因分词机制对此完全无能为力（中文 bigram 匹配不上英文单词），
成败全看嵌入模型能否把中文查询映射到英文片段附近——qwen3-embedding:8b 做得到但不稳定。
D 类同样：中文"多面体差分"只召回了中文论文，英文的 polytopic 论文两模式都漏。

### 6.3 对话级结论

- 8 题中 5 题两模式表现相当（含 Q2/Q5 两个缩写题 hybrid 更集中）；
- **vector 赢 2 题（Q6 综述、Q8 Gimli）**——都是自然语言长查询，与离线评测"长查询 hybrid 无优势"
  的结论互相印证；
- hybrid 没有输掉任何 vector 能答好的题。
- 一个值得注意的行为：**检索质量差时，LLM 会自动调用联网搜索工具补位**（Q6-hybrid、Q8-hybrid），
  答案看起来还行但来源已不是知识库——评估 RAG 效果时要看检索面板，不能只看答案通不通顺。

## 7. 综合结论与建议

### 7.1 结论

1. **默认保持 hybrid。** 它的最大价值是把"纯向量完全失明"的场景救回来：
   缩写（HDND/CPDI-ND 短查询下 vector MRR=0，hybrid=0.5）、精确论文标题片段、
   工具/模型名。这类查询在科研助手的使用中很常见，丢不起。
2. **hybrid 在长自然语言查询下不占优**（18 例 MRR 0.514 vs 0.451，但 R@10 反而更低 0.583 vs 0.639），
   两个机制性原因：BM25 常见词稀释（§5.3 现象一）和 RRF 深位挤出（现象二）。
   但"不占优"≠"明显更差"，18 例里 hybrid 明确输的只有 1.5 例。
3. **两种模式都救不了"中文长问题查英文文献"**（B/C 类多例全 0）——瓶颈在嵌入模型的跨语言
   语义桥接和 BM25 的分词机制，与检索模式选择无关。实用建议：查英文文献时用英文关键词问。
4. 延迟差异可忽略（0.12s vs 0.14s）。

### 7.2 若要进一步改进（按性价比排序，本轮未实施）

1. **查询预处理**：hybrid 前先从问题里抽关键词/去停用词再喂 BM25
   （比如用 LLM 或规则把"HDND 高阶差分神经区分器是什么"压成 "HDND 高阶 差分 区分器"），
   直接缓解现象一，预期对对话场景（天然是长问题）收益最大。
2. **BM25 最少命中词约束**：要求片段至少命中查询中 1 个**高区分度**词（IDF 高的词），
   而不是命中一堆常用词即可进榜。
3. **RRF 融合改进**：给两路不同权重、或把每路取 top 数从 max(k,8) 调大、
   或对"只在一路出现"的片段做降权微调，缓解现象二。
4. **跨语言**：入库时同时嵌入中文翻译（或换多语言更强的嵌入模型），或查询时自动检测
   "中文问题 + 库内多为英文"并做翻译桥接。

### 7.3 复现方式

```bash
python3 rag_test/eval3_offline.py   # 长查询离线评测（18 例 × 2 模式）
python3 rag_test/eval3_short.py     # 短查询电池（8 例 × 2 模式）
python3 rag_test/eval3_chat.py      # 对话级评测（2 会话 × 8 问；注意会在既有会话上追加）
```
